# LIPSIDE

**LIPSIDE** is a browser-based IDE for [LIPS](https://github.com/mandelbroetchen/lips) — the LLM-driven Iterative Project Synthesizer. It gives you a visual workspace to create pipelines, author build scripts, run LLM builds, and inspect outputs, all without leaving the browser.

> GitHub: [https://github.com/qia-uofa/lipside](https://github.com/qia-uofa/lipside)

---

## What is LIPS?

LIPS is a minimal Python framework for building file-system pipelines driven by large language models. You define a sequence of stages; each stage holds a `repo/` of working files and a `build/` of prompt scripts. LIPS assembles the context, calls the LLM, parses its output, and writes the resulting files — giving you a reproducible, version-controllable, iterative LLM workflow.

A typical pipeline looks like:

```
workspace/
└── my-pipeline/
    ├── config.json        ← LLM settings (model, tokens, temperature, messages)
    ├── format.md          ← output format instructions
    ├── .env               ← API key(s)
    ├── 1-prompt/
    │   ├── build/
    │   │   └── compile.md ← prompt/build script (TARGET=2-concept)
    │   └── repo/          ← human-authored seed files
    ├── 2-concept/
    │   ├── build/
    │   │   └── compile.md ← (TARGET=3-specs)
    │   └── repo/          ← LLM output from stage 1
    └── 3-specs/
        ├── build/
        │   └── identity.md ← final stage (no TARGET)
        └── repo/
```

LIPSIDE makes navigating, editing, and running these pipelines fast and visual.

## Features

**Pipeline management**
- Create new pipelines (pick provider, model, tokens, temperature, API key variable)
- Add threads (new stages) to existing pipelines
- Delete pipelines and stages with confirmation
- Rename and switch between pipelines via a dropdown

**Four view modes** — toggle with the tab bar or View menu
- `repo` — working files authored by you or written by the LLM
- `build` — prompt/build scripts that instruct the LLM
- `out` — logged run outputs (`messages_*.json`, `response_*.md`, `files_dict_*.json`)
- `graph` — visual pipeline graph showing stage flow and build scripts

**Editor**
- CodeMirror editor with syntax highlighting (Markdown, Python, Shell, JS, JSON)
- Multi-tab interface with per-tab dirty indicators
- Markdown live preview
- Find, replace, go-to-line, format JSON
- Auto-save on Ctrl+S

**Build system**
- Run any build script or entire stage with one click (▶ buttons)
- Streaming output panel with real-time LLM response
- Build queue — chain multiple builds; queue clears automatically on error
- Clickable graph edges trigger the associated build script

**Config & environment**
- Edit pipeline `config.json` via a form (provider, model, max tokens, temperature)
- Edit conversation message templates with a structured editor
- Edit workspace `.env` key-value pairs in-app
- API key variable dropdown populated from your `.env`

**File management**
- Create, rename, move, and delete files and folders via context menu
- Purge stage outputs (`out/`) or full stage contents (`repo/` + `out/`)
- Paste clipboard content as a new file

## Installation

**Prerequisites:** Python ≥ 3.10, [LIPS CLI](https://github.com/mandelbroetchen/lips) installed and on your PATH.

```bash
git clone https://github.com/qia-uofa/lipside
cd lipside
pip install -e .
```

---

## Usage

```bash
lipside --workspace /path/to/your/workspace
```

Then open [http://127.0.0.1:8765](http://127.0.0.1:8765) in your browser.

| Option | Default | Description |
|---|---|---|
| `--workspace` | `.` | Path to the LIPS workspace directory |
| `--host` | `127.0.0.1` | Host to bind to |
| `--port` | `8765` | Port to listen on |

---

## Workspace structure expected by LIPSIDE

LIPSIDE reads the workspace directory you pass to `--workspace`. It expects the standard LIPS layout — one subdirectory per pipeline, each containing `config.json`, `format.md`, `.env`, and one subdirectory per stage.

You can create all of this from inside LIPSIDE using **New Pipeline** and **New Thread**, or by running `lips create` from the command line first.

## Tech stack

- **Backend:** FastAPI + uvicorn, WebSockets for streaming build output
- **Frontend:** Vanilla JS, CodeMirror 5 (editor), marked.js (Markdown preview)
- **No build step** — the frontend is plain HTML/CSS/JS served directly by FastAPI
